## 3. 우리 팀의 제약조건 (기획 원칙)

1. 타겟 유저가 명확하고, 그들의 구체적 문제를 해결할 것
2. **플랫폼(양면 시장) 금지** — 일방 제공형 서비스만
3. 웹/앱 중심, 필요시 IoT까지 가능
4. **참신성**: 유사 서비스가 없을 것
5. **근거**: 실제 통계·뉴스로 문제가 입증될 것 (2020~21년 낡은 근거 말고 2025~26 최신)
6. 팀: 혼합(기획/디자인/개발), 장애 당사자 접근 경로 없음 → 인터뷰 섭외 필요

## 5. 확정 아이디어: 키오메이트(가칭)

폰 카메라로 키오스크 화면을 비추면 멀티모달 AI가 화면 구조를 읽고 "지금 뭘 누를지" 실시간 안내.
- 시각장애: 음성 유도 + 손가락 추적("오른쪽으로… 지금 누르세요") + 진동
- 발달장애·고령: 쉬운말 한 단계씩 + 눌러야 할 버튼 크게 표시
- **핵심 차별점: 키오스크 기기 협조·교체·연동이 전혀 불필요** (법이 실패한 공급자 접근의 반대 방향)
- 왜 지금: 멀티모달 LLM 화면 이해(computer-use)가 최근 1~2년에 실용화
- 정직한 범위 제외: 휠체어 높이 문제는 카메라로 못 풀므로 기획서에 명시
- 확장: ATM·무인민원발급기·병원 접수기 등 모든 무인 단말

→ **기획서 초안: `기획서-초안-v1.md`** (양식 5항목 구조, [보완 필요] 표시 포함)

## 6. 프리미스 챌린지 — "이게 진짜 문제인가?" (미해결 쟁점)

문제의 존재는 확실(법·통계로 공인)하나, **수요는 미검증**. 3가지 약점:
1. 워크어라운드 존재: 옆 사람에게 부탁 + **대형 프랜차이즈는 접근성 되는 자체 앱 보유** ← 심사 방어 취약점
2. 빈도 미상: 45%는 "선호" 통계지 "차단" 통계가 아님. 회피 행동은 데이터에 안 잡힘
3. 기술 실현성: 한 손 폰+한 손 터치, 지연, 반사, 시간초과 — "부탁하기"보다 나아야 함

**날카로운 피벗 각**: 직원도 앱 대안도 없는 곳 = 무인매장(24h)·무인민원발급기·병원 접수기·야간. 피벗해도 엔진(카메라 AI 에이전트)은 재사용 → 피벗 비용 낮음.

**킬러 인터뷰 질문 3개** (이 답이 기획의 생사 결정):
1. 최근 한 달간 키오스크/무인단말 앞에서 포기하거나 부탁한 적 몇 번? 어디서? (빈도+장소)
2. 프랜차이즈 앱으로 주문해봤나? 안 쓴다면 왜? (워크어라운드 품질)
3. 폰으로 비추면 음성 안내해주는 것 vs 그냥 부탁하기, 뭘 쓰겠나? (수용성)
→ "월 0~1회, 그런 데 안 감"이면 재난 대응으로 피벗.
