# 온음(Oneum) — 의도 확인형 구음장애 의사소통 보조

명세: ../아키텍처-명세서-v3.md / 기획서: ../기획서-초안-v2-온음.md

## 구조
- `mobile/` — **React Native (Expo) 앱** ← 메인. 제출·데모용
- `frontend/` — React + Vite 웹 (수직 슬라이스 참고용/웹 데모, 유지보수 대상 아님)
- `backend/` — FastAPI 무상태 프록시 (STT 중계 + m4a→16kHz WAV ffmpeg 변환). 프로필·이력은 전부 기기 내 저장. TTS는 기기 내장(expo-speech)이 기본 — 오프라인 동작(QA-04)
- `../asr-poc/serve.py` — **우리가 파인튜닝한 whisper 추론 서버(8020)**. 백엔드가 `ASR_PROVIDER=local`일 때 여기로 넘긴다. 학습 환경(torch·transformers)을 그대로 재사용하려고 별도 프로세스로 뒀다

## 실행

**데모 한 번에 띄우기** (파인튜닝 모델까지 붙은 상태, 실기기 시연용)
```bash
./run-demo.sh      # ASR(8020) → 백엔드(8010) → Expo 순서로 기동하고 LAN IP를 .env에 써 준다
```

수동으로 띄우려면:
```bash
# 백엔드 (키가 없으면 자동 mock 모드 — 키 없이도 전체 흐름 시연 가능)
cd backend && cp .env.example .env   # 키 발급 후 채우기
uv run python scripts/check_keys.py  # 키가 실제로 통하는지 먼저 확인
uv run uvicorn main:app --port 8010

# 모바일 앱 (별 터미널)
cd mobile
echo "EXPO_PUBLIC_API_URL=http://<개발PC의 LAN IP>:8010" > .env   # 폰에서 localhost는 폰 자신임!
npx expo start        # 폰의 Expo Go 앱으로 QR 스캔 (같은 와이파이 필수)

# (참고) 웹 데모
cd frontend && npm run dev   # http://localhost:5173, /api → 8010 프록시
```

## 현재 구현 상태
- [x] 녹음: 마이크 → 16kHz mono WAV 클라이언트 인코딩 (`src/lib/recorder.ts`)
- [x] 인식: `ASR_PROVIDER`로 공급자 선택 — mock / azure / local / **ensemble(명세서 4.3 기본값)**
- [x] **2-소스 앙상블**: 두 엔진을 `asyncio.gather`로 **동시** 호출(순차면 지연이 합쳐진다).
      역할이 다르다 — 로컬 파인튜닝 모델은 **정확한 1순위**, Azure는 `format=detailed`의
      **NBest 여러 개**를 맡아 확정 게이트(SF-04)의 '후보 2~3개'를 채운다.
      두 엔진이 같은 문장을 내면 남은 불확실성의 절반을 가산(BC-04 임시값).
      한쪽이 실패해도 나머지 결과로 진행한다
- [x] **파인튜닝 모델 서비스 연결**: `asr-poc/serve.py`가 whisper-small-v4-e3을 MPS에 올리고
      빔서치로 후보를 낸다. held-out 화자 8명 실측 — 완전일치 7/8, 평균 1.0초(목표 3초),
      틀린 1건은 신뢰도 0.58로 낮게 나와 확정 게이트가 잡아낸다
- [x] 확정 게이트: 임계값(임시 0.45) 기준 1순위 확인 / "인식하지 못했어요" + 후보 2~3개
- [x] 오류 복구: 다시 말하기 / 즐겨찾기(자리표시) / 직접 입력
- [x] 출력: 확정 문장 큰 글자 + TTS (앱은 기기 내장 음성 → 오프라인 동작)
- [x] **개인 표현 프로필 (SF-01)**: 상황별(일상/병원/매장) 문장 등록·삭제, 기기 내 저장(AsyncStorage)

- [x] **교정 이력 축적 (SF-07)**: (오인식→확정) 쌍 저장, 다음 재정렬 가산 + LLM few-shot 재료

### 판정기·재정렬 동작 검증
`npx tsx scripts/verify-quick.ts` — DD-05 6조건 판정기와 저위험 화이트리스트를 조건별로 전수 검사한다

### 재정렬 동작 검증
`npx tsx scripts/verify-rerank.ts` — 실제 오인식 시나리오로 확인 (기대 동작이 문서 역할):
- "무루 주세여"(conf 0.31) → **"물 한 잔 주세요"(0.828)** 로 복원, 상황이 바뀌면 0.678로 하락
- 교정 이력 있으면 0.996 → 1.296 상승
- 프로필에 없는 발화("내일 서울역에서 만나요")는 ASR 원문이 그대로 1위 유지

## 외부 서비스 (전부 선택 — 없으면 mock 모드)

| 항목 | 발급처 | 비고 |
|---|---|---|
| 음성인식 | **둘 다 필요** (`ASR_PROVIDER=ensemble`) — 파인튜닝 모델 + Azure `Speech service`(F0 무료) | 파인튜닝 모델만 쓰면 후보가 1개뿐이라 확정 게이트가 성립하지 않는다. N-best는 Azure가 준다 |
| LLM 복원 | **Gemini** — https://aistudio.google.com 무료 키 (`LLM_PROVIDER=gemini`, 모델 `gemini-3.6-flash`) | 설치 없이 키 하나. Ollama·Groq 등도 같은 코드로 지원 |

모델 이름을 추측할 필요 없다. `check_keys.py`가 **실제로 호출해 보고** 판정한다.
목록(`/v1beta/models`)에 있다고 쓸 수 있는 것이 아니기 때문이다 — `gemini-2.5-flash`는
목록에 남아 있으면서 호출하면 `404 no longer available to new users`를 돌려줬다.
모델을 못 쓰면 오류 메시지가 알려주는 대체 모델부터 차례로 시험해 쓸 수 있는 이름을 찾아 준다.

포털 메뉴 이름은 자주 바뀌므로 화면으로 판단하지 말고 `backend/scripts/check_keys.py`로 확인한다.
이 스크립트가 통과하면 그 키가 맞는 키다.
